# Accessibility and performance (task 23)

Requirement 9 of `.kiro/specs/reanimation-lab/requirements.md`. What is checked
automatically, how to rerun it, and what still needs a person.

## Automated checks

| Check | Where | Command |
|---|---|---|
| axe, WCAG 2.0/2.1/2.2 A and AA rules, every route and the main program-view states | `web/e2e/axe.spec.ts` | `npm run test:e2e -w web` (dev) and `npm run test:e2e:csp -w web` (production build under the CSP) |
| Keyboard only: skip link, the full happy path, visible focus at every stop, no focus traps | `web/e2e/keyboard.spec.ts` | same |
| Live region (9.2): status announced, progress at most every 5 s | `web/e2e/live-region.spec.ts` | same (the 5 s throttle test needs the dev server) |
| Roles and accessible names of the key views (Chromium's accessibility tree) | `web/e2e/a11y-tree.spec.ts` | same |
| Lighthouse budget (9.3): LCP < 2.5 s, initial JS < 200 KB gzipped | `web/perf/lighthouse.ts` | `npm run perf:lighthouse -w web` |
| 3D frame times and assets under 8 MB (9.4) | `web/perf/scene.perf.ts` | `npm run perf:scene -w web` |

The axe scan excludes nothing. The 3D scene and its still sit in an
`aria-hidden`, `inert` wrapper (they are decorative; the Prove panel carries the
status), so axe skips them anyway.

The Lighthouse and frame-time numbers come from a local run on the owner's
Apple M5 Pro with simulated throttling. They are lab estimates, not field data.

## Manual VoiceOver checklist (not yet run)

The automated checks read Chromium's accessibility tree. They do not prove what
VoiceOver says. Run this in Safari on macOS with VoiceOver on (Command-F5), on
the hosted site or `npm run web:dev` with `npm run api:dev`.

Use VO = Control-Option. Tick each item, and note the macOS, Safari and date.

**Landing (`/`)**
- [ ] First Tab lands on "Skip to content, link". Activating it moves to the main content.
- [ ] VO-U (rotor), Landmarks: banner, navigation "Primary", main.
- [ ] The 3D scene (or the still under Reduce Motion) is never read out.

**Morgue (`/morgue`)**
- [ ] Rotor, Headings: "The morgue" (level 1), then one level-2 heading per program.
- [ ] Each card reads as a list item named after the program, with the link, behaviours list and status (for example "Status, Alive").
- [ ] Activating a program link moves focus to the program page's main content.

**Program view (`/program/PAYROLL`)**
- [ ] "Prove it" is announced as a button. Pressing it announces "Proof started for PAYROLL." once, without stealing focus.
- [ ] When it finishes: "PAYROLL is alive: 2,000 cases matched GnuCOBOL." The counters are not read out on every update.
- [ ] Sabotage: the radio group is "Port to prove". Arrow keys move between mutants. The equivalent mutant reads its title, then "Equivalent".
- [ ] With a mutant selected, the diff region can be reached and read. Changed lines start with "Removed:" or "Added:".
- [ ] "Prove again" with the mutant: "PAYROLL relapsed: …" is announced.
- [ ] Counterexample: VO-Command-T (next table) reaches the input and output tables. Their captions are read, and the row headers (field names) are read when moving across cells. The differing field reads "Differs".
- [ ] "Copy command" announces "Copied the replay command."
- [ ] Below 900 px wide (zoom to 200 %, or narrow the window): the COBOL and TypeScript port tabs read as tabs, "1 of 2" and "2 of 2", and the arrow keys switch them.
- [ ] Statement links in the port pane read as buttons. Pressing one (when stacked) moves to the highlighted COBOL. Note: each button's name is its whole code block, which is long. Decide whether that is acceptable.

**Recorded fallback**
- [ ] Stop `api:dev`, press "Prove it": "The proof failed: …" is announced and "Replay the recorded proof" is reachable next.
- [ ] Replaying announces "Replaying the recorded proof for PAYROLL." and then "Recorded proof: …".

**Not found (`/no-such-page`)**
- [ ] "Nothing buried here" heading, and a link back to the morgue.
